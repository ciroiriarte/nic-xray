## 1. 📌 Decision summary

| Question | Decision |
|---|---|
| Put fleet analysis inside `nic-health.sh`? | ❌ No. `nic-health.sh` stays a single-host verdict tool with Nagios exit codes. Comparing across hosts is a separate job, done off-host after the sweep. |
| How many new tools? | **Two**, each with one job: `nic-sweep.sh` (collection) and `nic-report.py` (analysis and rendering). |
| Language | `nic-sweep.sh`: **Bash**, like the rest of the repo. `nic-report.py`: **Python 3, standard library only**, a documented exception to the "Modern Bash" rule (§3). |
| Canonical per-host artefact | `nic-health -O json`: it already carries `version`, `collected_at`, `level`, `mode`, `interval_s` and `capabilities`. CSV is derived from it, never the source of truth. |
| PDF | Optional: WeasyPrint, if installed (CSS Paged Media). HTML and Markdown need nothing beyond Python. |
| Installed names | `nic-sweep.sh` → `/usr/bin/nic-sweep`, `nic-report.py` → `/usr/bin/nic-report`, the same pattern as `nic-health.sh` → `/usr/bin/nic-health`. |
| Same repo and version? | ✅ Yes. Same repo, same tag, tandem `SCRIPT_VERSION` (`CLAUDE.md` §6). |
| Runs where? | `nic-sweep.sh` and `nic-report.py` run on an operator or jump host. Monitored nodes only need `nic-health` (and optionally `nic-xray`). |
| Recommendations | Generated by a versioned **diagnosis rule catalog** (§6.3.1) and ranked by service impact (§6.3.2), not hand-written. The executive summary is built from templates over the same facts (§6.3.3). |
| AI-written prose | **Optional and off by default.** `nic-report.py` stays offline: it can export a fact brief for Claude (or any model) and merge the returned text, checking every number against the facts (§6.7). |
| Branding | **Optional themes** (§6.8): colours, fonts, logos and labels from a folder outside the repo (`--theme DIR`). The repo ships only the default theme and a fictitious example. |
| Attribution | Every report says which tool and version generated it (§6.9), as `nic-xray` diagrams do. Themes cannot remove it. |
| Changes to node state | None beyond what `nic-health` already does (read-only). The sweep never installs packages. Shipping a script to `/tmp` is opt-in (§5.3). |

## 2. 🎯 Goals and non-goals

### Goals
- **Repeatable fleet sweeps.** One command collects `nic-health` from every host in an inventory, in parallel, into a fixed, versioned directory layout with a manifest of exit codes and failures.
- **Comparable data.** Every sweep records how it was collected (tool version, level, interval, time, host uptime), so later comparisons can state their limits instead of guessing.
- **Analysis beyond single-host verdicts.** Per-site and cross-site summaries, outliers against the fleet's own baseline (an optic far weaker than its peers), recurring patterns across sites, and comparison between two sweeps.
- **Actionable recommendations without hand analysis.** Each finding comes with a diagnosis, a concrete action (naming the switch port when LLDP is collected) and a priority based on service impact, in the same order an engineer would work through them.
- **Readable output.** Markdown, a self-contained HTML page and a print-quality PDF, plus JSON for automation.

### Non-goals
- Inventory discovery from MAAS, Juju, Ansible or a CMDB. The sweep takes a plain inventory file; adapters can generate it (§5.1).
- Long-term time-series storage or dashboards. Use Prometheus or similar. This tool compares snapshots.
- Sweep retention. Sweeps are small (a few MB per site); pruning, archiving or committing them is the operator's policy (cron, git, backup), so the tool has no delete path.
- Remediation. Like `nic-health`, the tools report and suggest; they never change NIC, switch or host configuration.
- Replacing `nic-health` checks. A per-host rule belongs in `nic-health.sh` (§8). `nic-report` only adds what needs more than one host.

## 3. ⚖️ Why two tools, and why Python for one

**Why not one tool:** collecting and analysing fail differently and run at different times. A sweep must run unattended over SSH, survive unreachable hosts and record exactly what happened. A report is re-run many times over the same data, often for other audiences. Keeping them separate also lets either side change without breaking the other: the contract between them is the sweep directory (§5.4).

**Why Bash for `nic-sweep.sh`:** it is process orchestration (ssh, timeouts, parallel jobs, files), which Bash does well and the repo already standardises on.

**Why Python for `nic-report.py`:** the report has to:
- parse RFC 4180 CSV with quoted fields that contain commas (legacy imports),
- compute medians, percentiles and robust outlier scores,
- write escaped HTML and feed a paged-media PDF engine.

Doing that in Bash means re-implementing a CSV parser and floating-point statistics on top of `awk` and `jq`. A first prototype was built in Python during a five-site, 121-host comparison in 2026-10, and that is the basis for this design.

**Guard rails on the exception:**
- Python 3.9 or newer, **standard library only** (`csv`, `json`, `statistics`, `html`, `argparse`, `pathlib`). No third-party import except the optional WeasyPrint, which is imported lazily only for `-O pdf`.
- One file, `nic-report.py`, following the same CLI conventions as the Bash scripts (long and short options, `--help`, `--version` printing `nic-report.py <version>`, `SCRIPT_VERSION` near the top).
- The exception covers **this script only**. `CLAUDE.md` §2 gets one line naming it.

### Alternatives considered

| Option | Why not |
|---|---|
| Bash + `jq` for everything | Feasible for text summaries; poor fit for statistics, robust CSV import and HTML/PDF. High maintenance cost for the report half. |
| Report tooling outside this repo | Loses the shared schema: a change to `nic-health` output would silently break an external report. Keeping both in one repo lets CI test them together. |
| Analysis inside `nic-health.sh` | Breaks its single-host contract and monitoring exit codes; it cannot see other hosts. |

## 4. 🏗️ Architecture

```
inventory.csv ──▶ nic-sweep.sh ──ssh──▶ host: sudo -n nic-health -O json -l deep -I 30
                      │                       (when installed) sudo -n nic-xray --all --output json
                      ▼
               sweeps/<site>/<UTC>/      ◀── contract (§5.4)
                      │
legacy CSV ──import──▶│
                      ▼
               nic-report.py ──▶ report.md · report.html · report.pdf · analysis.json
```

- `nic-sweep.sh` writes one directory per (site, sweep).
- `nic-report.py` reads one or more sweep directories (and legacy CSV through `--import`), normalises them into one record model (§6.1), runs the analyses (§6.3) and renders the output (§6.4).

## 5. 🛰️ `nic-sweep.sh`

### 5.1 Inventory

Plain CSV, one host per line, `#` comments allowed:

```
# site,host,address[,user]
SITE1,node-ctrl-01,10.0.0.15
SITE1,node-cmp-01,10.0.0.20,ops
```

- `host` is the name used in reports. `address` is what SSH connects to (IP or DNS name).
- Every field is validated against a strict pattern (`[A-Za-z0-9._-]+`; `address` also allows `:` for IPv6) before it reaches any command line. A failing line is reported and skipped; it is never passed to a shell.
- Generating the inventory from MAAS, Juju or Ansible is out of scope; the README gives one-line examples (e.g. `juju machines --format json | jq …`).

### 5.2 CLI sketch

```
nic-sweep.sh -f|--inventory FILE [-s|--site SITE]... [-J|--jump HOST] [-u|--user USER]
             [-p|--parallel N] [-T|--timeout SEC] [-o|--output-dir DIR]
             [-l|--level basic|deep] [-I|--interval SEC] [--no-xray]
             [--ship PATH] [--accept-new-hostkeys] [-n|--no-color] [-v|--version] [-h|--help]
```

| Option | Default | Meaning |
|---|---|---|
| `-f, --inventory` | required | Inventory file (§5.1) |
| `-s, --site` | all | Only sweep these sites (repeatable) |
| `-J, --jump` | none | SSH jump host (`ssh -J`) |
| `-u, --user` | current user | Default SSH user (per-host override in the inventory) |
| `-p, --parallel` | 8 | Hosts swept at once |
| `-T, --timeout` | interval + 300 s (deep) / + 120 s (basic) | Per-host wall-clock limit for `nic-health`; `nic-xray` has its own 120 s. Deep mode queries each mlx5 port (10 s cap each); real deep sweeps took 35–90 s per host |
| `-o, --output-dir` | `./sweeps` | Root of the sweep tree (§5.4) |
| `-l, --level` / `-I, --interval` | `deep` / `30` | Passed to `nic-health`. 30 s, because shorter windows miss bursty link errors (see `nic-health.md` §5) |
| `--no-xray` | off | Skip `nic-xray`. By default the sweep also collects `nic-xray --all --output json` (`--lacp --vlan --bmac --optics --physical`: LLDP peer, LACP, optics for every vendor, VLANs seen via LLDP, NUMA node and slot) on every host where `nic-xray` is installed; hosts without it are recorded as `xray: absent` in the manifest, not as a failure |
| `--ship PATH` | off | Copy a local `nic-health.sh` to the host's `/tmp`, run it, delete it. For hosts without the package. Default: require `nic-health` (or `nic-health.sh`) on the remote `PATH` |
| `--accept-new-hostkeys` | off | `StrictHostKeyChecking=accept-new`. Default leaves SSH's own policy in place |

A missing `--inventory` prints the usage message (`CLAUDE.md` §3).

### 5.3 Execution per host

1. `ssh -o BatchMode=yes -o ConnectTimeout=10 [-J jump] user@address`. Never prompts.
2. Remote command, fixed and quoted (no remote `eval`):
   `sudo -n nic-health -O json -l <level> -I <interval>`; with `--ship`, the shipped path instead, removed on exit.
3. stdout → `nodes/<host>.json`, stderr → `nodes/<host>.err`; host, address, status, exit code, duration, nic-xray status and verdict → `MANIFEST.tsv`.
4. Classify each host: `ok` (JSON parsed; any verdict), `ssh-fail`, `sudo-fail` (`sudo -n` refused), `tool-missing`, `timeout`, `bad-output` (not valid JSON). JSON validity is strict: `jq` checks the shape, plus a separate check for bare non-finite numbers (`inf`, `-inf`, `nan`), which JSON forbids but `jq` (1.6 and 1.7) accepts. `nic-xray` < 2.13.0 writes `-inf` for optics without light (#24): such output is kept, marked `failed`, and noted in `.err`. `jq` 1.6 also exits 0 on empty input with `-e`, so output must be non-empty. The `nic-health` `schema_version` is not checked: 1 and 2 (typed `metrics`, §7 P2) are both collected as they are, and `merged.csv` keeps its columns (metrics are JSON only); a non-finite number inside `metrics` is `bad-output` like anywhere else.
5. A progress bar on stderr when stdout is a terminal (`CLAUDE.md` §3); none with `-n` or when output is redirected.
6. Requirements on the operator host: Bash 4.4+, `ssh`, `timeout`, `jq`, `sha256sum`, `getopt`. `jq` is the one addition to the repo's tool set; it runs only on the operator host, never on the swept nodes.

### 5.4 Output layout (the contract)

```
sweeps/<site>/<YYYYmmddTHHMMSSZ>/
├── sweep.json          # nic-sweep version, args, inventory sha256 and skipped lines, start/end, host counts
├── MANIFEST.tsv        # host  address  status  exit_code  duration_s  xray  verdict
├── merged.csv          # site,hostname,collected_at,version,level,interval_s,uptime_s,boot_id + record columns
└── nodes/
    ├── <host>.json     # canonical: nic-health -O json, unmodified
    ├── <host>.err
    └── <host>.xray.json   # when nic-xray is installed (unless --no-xray)
```

- `nodes/*.json` are kept byte-for-byte as returned. Everything else can be regenerated from them.
- `merged.csv` is a convenience export. It **always carries the collection metadata columns**, which plain `nic-health -O csv` does not, so a merged CSV taken out of context still says how it was collected.
- `sweep.json` has its own `schema_version`. `nic-report.py` refuses a newer major version than it knows.

### 5.5 Exit codes

| Code | Meaning |
|---|---|
| 0 | Every host collected, all verdicts OK or N/A |
| 1 | Every host collected, at least one WARN, no CRIT |
| 2 | At least one CRIT (even if some hosts failed to collect) |
| 3 | No CRIT, but at least one host not collected; or no WARN and at least one UNKNOWN verdict; or usage error |

Precedence: CRIT > a host not collected > WARN > UNKNOWN verdict > OK. CRIT outranks a collection failure so that a real fault is never hidden behind one unreachable host; among verdicts the order is `nic-health`'s own. A worker that ends without a result still gets a manifest line (`bad-output`, exit `-`), and an empty result set is UNKNOWN. `MANIFEST.tsv` always lists the failures.

## 6. 📊 `nic-report.py`

### 6.1 Normalised record model

Each `nic-health` result becomes one row, enriched with its collection context:

| Field | Source |
|---|---|
| `site`, `host` | inventory / sweep path (import: argument and file name) |
| `role` | derived from `host` with `--role-regex` (e.g. `^[^-]+-[^-]+-(?P<role>[a-z]+\d+[a-z]*)-\d+`); empty if not set |
| `collected_at`, `tool_version`, `level`, `mode`, `interval_s` | `nic-health` JSON envelope; `null` for legacy CSV |
| `uptime_s`, `boot_id` | JSON envelope once P1 lands (§7); else `null` |
| `severity`, `scope`, `target`, `check_id`, `value`, `unit`, `threshold`, `evidence`, `hint`, `ref` | the record |
| `metrics` | structured values: from `nic-health`'s typed `metrics` (P2, §7, JSON `schema_version` 2) value by value, else parsed from `evidence` by tested extractors (§6.2); service-impact facts (P3) only from typed `metrics` |

### 6.2 Inputs and legacy import

- **Sweep directories** (§5.4): the normal input. Any number, from any sites.
- **`--import SITE PATH...`**: CSV collected by hand before `nic-sweep` existed. The importer must cope with what real collections look like:
  - one file per host with no `site`/`hostname` columns (host taken from the file name up to the first `_` or `.`),
  - merged files that already carry `site,hostname`,
  - CRLF line endings and leading blank lines (terminal captures),
  - mixed `nic-health` versions in one site.
  Imported rows get `null` collection metadata, and the report lists them under coverage caveats.
- **Evidence extractors** (the fallback since P2): one small, unit-tested function per value (Rx/Tx power, module temperature, error totals since boot, carrier changes, discards, AER totals, effective/raw BER, FEC mode, module compliance). Each has fixtures taken from real `nic-health` output. A value that does not parse is `null`, never `0`.
- **Typed metrics first** (P2): when a record carries `metrics`, each value is read from it with the extractor's semantics (e.g. a counter of 0 next to non-zero ones of the same check stays `null`, as in the evidence) and type-checked as untrusted input; a missing or mistyped value falls back to that value's extractor, so older JSON, CSV imports and odd input never fail. The report is identical with or without typed metrics apart from the coverage line that counts them (Phase 6 exit criterion, tested).

### 6.3 Analyses

| # | Analysis | Notes |
|---|---|---|
| A1 | **Coverage and comparability** | Hosts, roles, ASICs, ports, ports with link, deep checks evaluated, FEC mix. Lists mixed tool versions, intervals and dates, and every host not collected. |
| A2 | **Verdict summary** | Per site and per role: CRIT/WARN/UNKNOWN counts, hosts clean (% of hosts). |
| A3 | **Findings** | All WARN/CRIT/UNKNOWN, grouped by site → host → target, with evidence and hint. |
| A4 | **Fleet baselines and outliers** | Per metric over **ports with link only** (dark spares read about −40 dBm and would skew everything): min, p5, median, max. Outliers by robust score (median/MAD) **and** an absolute floor, e.g. Rx ≥ 5 dB below the median for the same module compliance. Also: highest error totals since boot (with rate per hour of uptime once P1 lands), carrier changes ≥ N, discards, PCIe below capability vs slot-limited. |
| A5 | **Cross-site patterns** | Group findings and outliers by (role, check, port position such as bond member / breakout lane) across sites. Prototype example: the same low-Rx bond leg on the same storage role at two sites. Implemented as: within a site, the same issue on the same port/ASIC in ≥ 2 collected hosts of a role; across sites, the same issue on the same role at ≥ 2 sites (ports may differ). Related checks form one issue family (symbol/CRC/BER → "link errors"; flaps and link-downs → "link instability"). Multi-site reports show both. Without roles a site's hosts form one group and cross-site patterns are skipped, with a note. Outliers: ≥ `-d` dB below the module type's median **and** robust z ≤ −3.5 (margin alone when MAD = 0); one fact pass over the baseline population so a port's module type is the same in baseline and report. |
| A6 | **Sweep comparison** | Two sweeps of one site: new, resolved and persisting findings; counter growth between sweeps, reset when `boot_id` changed (P1). |
| A7 | **Known tool issues** | Optional `--suppress FILE`: `{"schema_version": 1, "suppress": [{"check_id", "reason", "match"?, "hosts"?, "sites"?}]}` (`match`: regex searched in the target and the first 4096 characters of the evidence; `hosts`: regex on the host name; unknown keys or bad regexes are input errors; unused rules and unselected sites are warned about). Matching WARN/CRIT/UNKNOWN results leave findings, verdict counts, the PCIe list and patterns; a host's verdict is recomputed as its worst remaining severity and shown as adjusted. Baselines and outlier lists are measurements and stay; patterns built from a suppressed check are dropped. Reported in its own section (rule, reason, count, every result) and in JSON, so nothing is silently dropped; coverage notes that suppression was applied. |
| A8 | **Diagnosis and recommendations** | Evaluates the rule catalog (§6.3.1) over per-port, per-host and per-group facts, ranks the matches (§6.3.2) and writes the recommendations and executive summary (§6.3.3). |

Thresholds are options with defaults (`--rx-delta-db 5`, `--flap-min 100`, …) or a JSON config file. TOML is skipped because `tomllib` needs Python 3.11.

**Implementation (Phase 8, A6).** What the code does where the row above left room:

- **Selection.** `-C`/`--compare OLD NEW` takes two sweep directories and replaces every other selection: with a `SWEEP_DIR`, `-R`, `-s`, `-a`, `-i`, `-b all` or `-P` it is a usage error (exit 3). Both must be sweeps of the same site (`site` in `sweep.json`), two different directories (compared by real path), and OLD's directory name (its UTC time) strictly earlier than NEW's; anything else is an input error (exit 1). The report is NEW's ordinary single-site report, every existing section computed from NEW alone, plus the comparison; OLD feeds only A6 (and is not searched for earlier LLDP neighbours).
- **Findings.** Keyed by `(host, target, check_id)` over the active WARN, CRIT and UNKNOWN results; two results with one key count as the worse. Only in NEW is **new**, only in OLD **resolved**, in both **persisting** with the old and the new severity (a change is flagged and shown as `WARN → CRIT`). `-S` applies the same rules to both sweeps, and a key with a suppressed result in either sweep is in none of the lists (the section gives their number), so a rule whose `match` hits the evidence of one sweep only cannot fake a new or resolved finding. Order: severity, host, target, check.
- **Hosts.** Only hosts collected and readable in both sweeps are compared. The others are listed as not comparable with their status in each sweep (`absent` when that sweep's manifest does not list the host); their findings are neither new nor resolved.
- **Counters and resets.** Per port present in both sweeps of a comparable host: the since-boot (or since driver load) totals the report already extracts, symbol errors (`rx_symbol_err_phy`), carrier changes and receive discards (`rx_discards_phy`). The time between them is NEW `collected_at` − OLD `collected_at` of that host, else the difference of the sweep times. With both `boot_id`s known, equal means the same boot: growth = new − old with a rate per hour, and new < old is a **reset** on the same boot (driver reload or counter clear), never negative growth. A different `boot_id` marks the host **rebooted**: the NEW value is shown "since reboot" and no growth is computed. Without a `boot_id` in either sweep (nic-health older than 2.13), a reboot is inferred from uptime: NEW `uptime_s` more than 5 minutes (`UPTIME_SLACK_S`) below OLD `uptime_s` + the time between the two `collected_at` values (so a reboot after OLD whose new uptime already exceeds OLD's is caught), or, without both `collected_at`, NEW `uptime_s` < OLD `uptime_s`; with no uptime either the boot is **unknown**: a decrease is reported as a reset, growth is shown with "a reboot cannot be ruled out". Listed are ports with growth > 0, a reset, or a non-zero value on a rebooted host (a port whose every counter is 0 after the reboot adds nothing); order host, port.
- **Output.** A last section, `N. Changes since <OLD>` (8, or 9 after the suppressed known issues), with new, resolved and persisting findings, hosts rebooted, with unknown boot or not comparable, and counter growth; it is in the PDF contents like every section. The executive summary gains one line: time between the sweeps, new / resolved / persisting counts, hosts rebooted and not comparable. JSON gains a top-level `comparison` object (both sweeps' stamp and path, `elapsed_s` overall and per host with its basis, the lists above, `rebooted`, `boot_unknown`, counter rows with old, new, growth, per-hour rate and state). Host-written text goes through the same sanitisers as elsewhere. Without `-C` every output is byte-identical to before.
- **Not in this phase.** A8 is unchanged: no rule fact reads the comparison. Growth between sweeps (for example `phy_err_growth_between_sweeps`) is a possible later fact for the rule catalog.

#### 6.3.1 Diagnosis rule catalog (A8)

A finding says *what* is wrong; a recommendation says *why* and *what to do*. The prototype report's recommendations came from a short list of reasoning steps that were applied by hand. They are encoded as data:

- **File:** `nic-report-rules.json`, shipped with the package (e.g. `/usr/share/nic-xray/`), with its own `schema_version` and a `catalog_version` printed in every report. `--rules FILE` (repeatable) adds or overrides rules by `id`.
- **Site rules stay out of the shipped catalog.** The packaged catalog is generic and public. Site knowledge (local cabling standards, known bad part batches, accepted exceptions) goes in a separate rules file kept with the site data, e.g. next to the inventory, and is layered on with `--rules`. Later files override earlier ones by `id`, and the report lists every catalog file and version it loaded.
- **Facts:** before rules run, the report computes named facts for each port, ASIC, host and group (same role within a site, same role across sites). Facts come from records, `metrics` (P2), service-impact data (P3) and fleet baselines (A4):

| Fact | Scope | Meaning |
|---|---|---|
| `rx_delta_host_db` / `rx_delta_fleet_db` | port | Rx power minus the median of linked peers with the same module compliance (host / fleet) |
| `phy_err_growing`, `phy_err_rate_s` | port | Symbol/CRC errors grew in the window; rate per second |
| `phy_err_total`, `phy_err_rate_h_uptime` | port | Since-boot total; average per hour of uptime (P1) |
| `carrier_changes`, `link_down_recent` | port | Since driver load; link-down messages in the look-back window |
| `fec_mismatch`, `deep_opcode` | port | Module requires FEC that the link does not run; `mstlink`/`mlxlink` troubleshooting opcode |
| `in_use`, `bond_link_failures`, `has_traffic` | port | Service impact (P3, `nic-health`) |
| `peer_switch`, `peer_port`, `peer_descr` | port | LLDP neighbour (`nic-xray`: `switch_name`, `port_name`, `port_descr`) |
| `bond`, `lacp_aggregator`, `lacp_partner` | port | Bond membership and LACP state (`nic-xray`: `parent_bond`, `lacp_status`); `bond` falls back to P3 when `nic-xray` is absent |
| `rx_dbm`, `tx_dbm`, `optics_status`, `module_type`, `module_vendor`, `lanes` | port | Optics for **every vendor** via `ethtool -m` (`nic-xray`: `optics.*`, per-lane values on QSFP). For ports where `nic-health` deep mode also reads the module, the deep value wins (§6.3.1, source precedence) |
| `speed_mbps`, `mtu`, `vlans` | port | Negotiated speed, MTU and the VLANs the switch advertises over LLDP (`nic-xray`: `speed_duplex`, `mtu`, `vlan`) |
| `numa_node`, `slot_label` | ASIC | Physical placement for work orders (`nic-xray`: `numa_node`, `pci_slot`) |
| `bond_speed_mismatch`, `bond_mtu_mismatch`, `bond_lacp_split`, `bond_peer_switches` | bond | Derived across a bond's members: unequal speed or MTU, members on different LACP aggregators or partner MACs, and the set of switches the members reach |
| `role_vlan_drift` | group | Same-role hosts in a site whose per-port VLAN sets differ from the role majority |
| `pcie_below_cap` | ASIC | Trained below what card and slot support (not slot-limited) |
| `role_share(check)` | group | Fraction of same-role hosts in the site failing the same check |
| `sites_with(pattern)` | fleet | Sites where the same (role, check, port position) pattern appears |

- **Rule shape:** a declarative condition over facts. There is no `eval`: the only operators are `eq ne gt ge lt le in exists`, nested in `all`/`any`. Each rule also has a diagnosis, an action, a base priority and a reference:

```json
{
  "id": "OPT-ATTEN-ACTIVE",
  "scope": "port",
  "when": { "all": [
    { "fact": "rx_delta_host_db", "op": "le", "value": -5 },
    { "fact": "phy_err_growing", "op": "eq", "value": true } ] },
  "diagnosis": "Attenuated optical path: Rx {rx_dbm} dBm is {rx_delta_host_db} dB below its peers and errors are growing",
  "action": "Clean or inspect both fibre ends, then replace the optic and the cable leg to {peer}",
  "priority": 1,
  "ref": "docs/design/nic-health.md §6.2"
}
```

- **Starter catalog:** these rules reproduce every recommendation of the 2026-10 prototype report:

| Rule | Condition (summary) | Diagnosis → action | Base priority | Explains |
|---|---|---|---|---|
| `OPT-ATTEN-ACTIVE` | `rx_low` (Rx ≥ `-d` dB below its peers) **and** `active` = 2 (errors growing, link drops or flaps in the window) | Attenuated path → clean/replace fibre, optic, cable leg | 1 | module, link errors, flaps, look-back, PHY link-downs, link state |
| `OPT-ATTEN-LATENT` | `rx_low`, `phy_err_total` > 0 **and** `active` < 2 (nothing grew in the window, or there is no window) | Same fault between bursts → same action, before the next burst | 2 | module, link errors |
| `OPT-LANE` | `rx_low` false **and** errors growing | Marginal transceiver or breakout lane (not attenuation) → replace the optic or that lane; check the peer port | 1 | link errors |
| `LINK-FLAP-HIST` | `flaps_high` (`carrier_changes` ≥ `--flap-min`) **and** `active` < 2 | Past flapping → watch with a longer `-I`, inspect the cable | 4 | flaps, PHY link-downs |
| `PCIE-SHARED` | `pcie_below_cap` on ≥ 2 hosts **and** at least half of the role's hosts (`role_hosts_pcie`, `role_share_pcie`) | Shared cause → check the BIOS PCIe slot speed/bifurcation profile before replacing hardware | 3 | PCIe link |
| `PCIE-SEAT` | `pcie_below_cap` on this host only of its role | Seating/riser → reseat the card | 3 | PCIe link |
| `PCIE-SEAT-FEW` | `pcie_below_cap` on ≥ 2 hosts but fewer than half of the role's | More likely seating or a riser on each than a shared cause → reseat the card | 3 | PCIe link |
| `PCIE-DISCARDS` | `pcie_below_cap` **and** RX buffer discards growing on the ASIC's ports | Bus bottleneck causing drops → raises `PCIE-SHARED`/`PCIE-SEAT`/`PCIE-SEAT-FEW` by one level | modifier | discards |
| `FEC-MISMATCH` | `fec_mismatch` | Configuration → enable RS-FEC on the NIC and the switch port | 2 | FEC |
| `SIG-INTEGRITY` | the troubleshooting recommendation says "signal integrity", or `deep_opcode` 15 | Lane/cable quality → inspect or replace the cable | 3 | troubleshooting |
| `PATTERN-CROSS-SITE` | `sites_with` ≥ 2 | Systemic weakness (cabling standard, part batch) → audit that position at every site | 2 | the A5 issues of its places |
| `LAG-SPLIT` | `bond_lacp_split` (members on different aggregators or partners) | Mis-cabled or misconfigured LAG: part of the bond is not aggregated → check the switch LAG/MC-LAG membership of `{peers}` | 1 | — |
| `BOND-SPEED-MISMATCH` | `bond_speed_mismatch` | A member negotiated a lower speed (wrong optic, autoneg, breakout mode) → check the optic type and switch port speed | 2 | — |
| `BOND-MTU-MISMATCH` | `bond_mtu_mismatch` | Members with different MTU drop large frames on one path → align the MTU on the bond members | 2 | — |
| `BOND-SINGLE-SWITCH` | bond meant to be redundant (≥ 2 members) and `bond_peer_switches` has one entry | No switch redundancy: losing that switch takes the bond down → re-patch one member to the second switch | 3 | — |
| `VLAN-DRIFT` | `role_vlan_drift` | A host's switch port advertises a different VLAN set from its role peers → compare switch port configuration (only as reliable as the switch's LLDP VLAN TLVs) | 3 | — |
| `OPT-WEAK-ANY-VENDOR` | `rx_low` with `optics_source` `nic-xray` (no `nic-health` deep data), where neither `OPT-ATTEN-*` rule applies (`active` < 2, no symbol errors since boot) | Same action as `OPT-ATTEN-*`, for NICs without vendor tools (Intel, Broadcom, …) | 2 | module |

#### 6.3.2 Prioritisation

Every matched rule becomes one recommendation. They are sorted by a score built from:

1. **Base priority** from the rule (1 = act now … 4 = informational).
2. **Activity:** growing in the window counts more than historical only.
3. **Service impact (P3 and `nic-xray`):** a bond member with link failures or traffic raises the priority; a port that is up but unused (no address, no upper device, no traffic) lowers it by one level. In the prototype, this put the flapping bond member first and the idle port with errors second, despite both being CRIT.
4. **Breadth:** a cross-site pattern is listed once, linking the individual findings.

**Source precedence.** When `nic-health` and `nic-xray` both report a value, `nic-health` wins for health data (link state, errors, deep module readings with thresholds and lane flags), and `nic-xray` fills in what `nic-health` does not collect (LLDP, LACP, VLANs, placement, optics on non-mlx5 or non-deep ports). The report's coverage section (A1) states, per site, how many ports had optics from deep mode, from `nic-xray`, or none.

**Not covered by `nic-xray`:** bond link-failure counts and per-port traffic. `nic-xray --metrics` can sample live throughput, but it needs a sampling interval and is not part of the sweep's default command, so both stay P3 in `nic-health`.

Matches on the same target are merged, so one port gives one recommendation that cites every rule that fired. A finding no rule explains is listed as "unexplained, needs review", so gaps in the catalog stay visible.

**Implementation (Phase 7).** What the code does where the sketch above left room:

- **Derived facts.** Rules test a few named facts instead of raw thresholds: `rx_delta_host_db` needs at least 3 linked peers of the same module type on the host (§8) and is low at ≥ `-d` dB below their median; `rx_delta_fleet_db` is low by the A4 outlier test (≥ `-d` dB below **and** robust z ≤ −3.5); `rx_delta_db` is the lower of the two and `rx_low` is true when either is low; `active` is 2 when symbol errors grew, the kernel logged link-downs in the look-back window or the link flapped in the window, else 1 when `phy_err_total` > 0 or `flaps_high`, else 0 (without a sampling window nothing can grow, so `active` < 2 also holds then); `flaps_high` is `carrier_changes ≥ -f`. Optical readings outside −60 … +30 dBm (`OPTICAL_DBM_RANGE`) are dropped, from deep mode, typed metrics and nic-xray alike, and a module range is used only when both bounds parse. Per-scope fact names and types are a table in the script (`RULE_FACTS`); the JSON report lists every fact with the number of targets that have it, so a fact that is always absent with current data shows 0. With current data `phy_err_rate_h_uptime` needs P1, `in_use`/`has_traffic`/`idle`/`bond_link_failures` need P3, and the LLDP, LACP, VLAN and placement facts need nic-xray in the sweep.
- **Templates** take `{fact}` or `{fact|fallback text}`; a placeholder must name a fact of the rule's scope (checked at load time). Values come from untrusted hosts and switches and are sanitised by each renderer like any host text.
- **Starter priorities** (the table above) differ from the first sketch of this catalog in three places, so that the prototype's order comes out and no port gets the same action twice: `PCIE-SHARED` starts at 3 (sketched 2) and `PCIE-DISCARDS` raises it by one level; `LINK-FLAP-HIST` is 4, informational (sketched 3); `OPT-WEAK-ANY-VENDOR` is a fixed 2 (sketched "as `OPT-ATTEN-*`"), because a nic-xray reading with errors or link drops now gets the `OPT-ATTEN-*` rules themselves. `PCIE-SEAT` (sketched "a single host") is split: `PCIE-SEAT` for one host of the role and `PCIE-SEAT-FEW` for two or more but fewer than half, so the text never says "this host only" for several. `SIG-INTEGRITY` matches the troubleshooting recommendation text "signal integrity" or opcode 15.
- **Explained findings** are per check: each rule has `explains`, the nic-health check ids it accounts for (at most 64, validated), defaulting to the checks whose facts its `when` reads (`FACT_SOURCES`; `active` counts as symbol errors, flaps and look-back). A finding is explained only when a recommendation on its target, a modifier on it, or a cross-site pattern listing its place has a rule whose `explains` names its check; for a pattern, only the checks of that place's A5 issue. Every starter rule sets `explains`; the bond and VLAN rules explain no nic-health check. The JSON `covers` lists `[site, host, target, check]`. Discard ports pinned to an ASIC count only when a rule there explains `mlx5.nic.discards`; when they were pinned as the host's only ASIC below capability (no nic-xray device, no predictable name), the sentence says the mapping is assumed. A modifier's diagnosis and action are both shown ("Also:").
- **Template fallbacks** never claim a zero they did not measure: a window count that is absent reads "an unknown number of". Each placeholder is cut at 200 characters, and a list shows its first 6 items and "… and N more".
- **Score:** base priority − modifier raises − 0.5 for a bond member with bond link failures, link drops or traffic in the window + 1 for a port that is up but unused (P3); the printed level is the score rounded up, clamped to 1–4. Ties break on activity, service impact, number of hosts and place, so the order is stable. Recommendations that differ only by host are merged into one that lists the hosts.
- **Facts that moved or narrowed:** `role_vlan_drift` is a port fact (with `role_vlans`, the role majority for that port); `role_share(check)` exists as `role_share_pcie`, the only check the starter catalog needs it for; `sites_with` counts sites per role across the A5 issue families (the port position may differ, as in A5); `LAG-SPLIT` names the members' switch ports as `{peers}` at bond scope. A port is `idle` only when nic-health says it is not in use **and** the window measured no traffic; with traffic unknown it is not lowered. A host without a `nodes/<host>.xray.json` simply has no nic-xray facts; only a malformed or oversized one is a caveat.
- **LLDP from earlier sweeps:** a port with no LLDP neighbour in the reported sweep (typically its link was down at collection) takes the newest one the same host saw on that interface in an earlier sweep of the site, within `-L`/`--lldp-lookback` days (default 30, at most 50 sweeps read) and never after the reported sweep. The fact `peer_from_sweep` names that sweep; the recommendation shows it next to the peer and coverage lists the ports. Such a neighbour only names the peer for the work order: bond redundancy, LAG and VLAN facts use the reported sweep alone, so no diagnosis rests on stale cabling data.
- **Section order:** the executive summary is section 1 and the recommended actions section 7 (after the patterns), followed by suppressed known issues.

#### 6.3.3 Report narrative

The executive summary and the recommendations are built from **templates filled with facts**. Each sentence comes from a rule's `diagnosis` and `action` text with placeholders (`{rx_dbm}`, `{peer}`, `{bond_link_failures}`, …), and site status comes from A2. The text is plainer than a hand-written report but always accurate, and it is identical on every run over the same data.

### 6.4 Output

| `-O` | Content |
|---|---|
| `md` (default) | Report as Markdown: what an operator reads in a terminal or commits next to the data |
| `html` | One self-contained file: inline CSS, no external fonts, scripts or images (reports contain host and switch names). Light and dark theme, readable on a phone, severity badges |
| `pdf` | WeasyPrint over the same HTML plus a print stylesheet: cover page, contents with page numbers (`target-counter`), running header with the section (`string-set`), "Page N of M" footer, a page break before each section, **landscape named pages only for wide tables**. Fonts: name real installed families first and **do not name the emoji font explicitly**. Fontconfig then picks it for digits, which happened in the prototype; emoji still render through fallback |
| `json` | The computed analyses (A1–A8), facts and rule matches, for automation, tests and the AI brief (§6.7) |

- `--title`, `--classification` (footer label, e.g. "confidential site data") and `--output FILE`.
- Without WeasyPrint, `-O pdf` exits with a clear message naming the package.
- `--per-site` writes one report per site in addition to the combined one.

### 6.5 CLI sketch

```
nic-report.py [-O md|html|pdf|json] [-o|--output FILE] [-i|--import SITE PATH...]...
              [-r|--role-regex RE] [-d|--rx-delta-db DB] [-f|--flap-min N] [--config FILE]
              [-S|--suppress FILE] [-u|--rules FILE]... [-L|--lldp-lookback DAYS] [-P|--per-site] [-C|--compare OLD NEW]
              [-R|--sweep-root DIR] [-s|--site SITE]... [-a|--at DATE] [-b|--baseline scope|all]
              [-T|--theme DIR] [-X|--strict-theme] [--ai-brief FILE] [--audience engineer|management|field]
              [--narrative FILE] [--strict-narrative]
              [-t|--title TEXT] [-c|--classification TEXT] [-v|--version] [-h|--help]
              [SWEEP_DIR...]
```

With no sweep directory, no `--sweep-root` and no `--import`, it prints the usage message.

Exit codes: `0` report written, `1` input error (unreadable input, unknown schema or site, a site selected twice, no data for the selection, output file not writable), `3` usage error. Odd input never ends in a traceback; a collected host whose `nodes/<host>.json` is missing or malformed is reported as `unreadable-result` (listed with the hosts not collected) instead of failing the whole report. Under `-R`, a sweep's `site` must match its directory. Options added in later phases get short forms where a free letter exists; long options are never abbreviated.

### 6.6 Report scope: one site, some sites or all

The same tool produces a single-site report or a multi-site comparison. Only the selection changes, and the report adapts its sections to it.

**Selecting sites**

| How | Example | Selection |
|---|---|---|
| By name from the sweep tree | `nic-report.py -R sweeps -s SITE1` | The latest sweep of SITE1 |
| Several by name | `nic-report.py -R sweeps -s SITE1 -s SITE3` | The latest sweep of each |
| All sites in the tree | `nic-report.py -R sweeps` | The latest sweep of every site found |
| A point in time | `… --at 2026-10-23` | Per site, the latest sweep on or before that date (UTC). Sites with none are listed as missing, not dropped silently |
| Explicit folders | `nic-report.py sweeps/SITE1/20261026T135700Z …` | Exactly those sweeps (for reruns and tests) |
| Legacy data | `--import SITE PATH…` | Mixed freely with any of the above |

Site names are validated against the sweep tree. An unknown `-s` is an error that lists the available sites. Two sweeps of the same site in one selection need `-C`/`--compare OLD NEW` (A6), which reports on NEW and adds the changes since OLD; otherwise it is an error, so one site is never counted twice.

**How the report adapts**

| Section | One site | Two or more sites |
|---|---|---|
| A1 Coverage | Columns per **role** | Columns per **site** (as in the prototype) |
| A2 Verdicts | Per role, per host | Per site, then per role |
| A3 Findings | By host | By site → host |
| A4 Baselines/outliers | Within the site (or the inventory, see `--baseline`) | Across the selected sites |
| A5 Patterns | **Within the site:** same check on the same port position across hosts of a role (e.g. 3 of 4 storage nodes) | **Across sites:** the same pattern at two or more sites |
| A8 Recommendations | Same rules. `PATTERN-CROSS-SITE` cannot fire; `role_share` rules can | All rules |
| Title, cover | "NIC Health: SITE1" | "NIC Health: cross-site comparison (SITE1 · SITE2 · …)" |

**Baseline scope (`--baseline`)**

- `scope` (default): baselines and outliers use only the selected sites, so the report is self-contained.
- `all`: baselines use **every site in the sweep tree** (latest sweep each) while findings and recommendations still cover only the selection. Use it for one small site, where a handful of ports makes a weak baseline: "SITE1's −8.8 dBm port is 8.7 dB below the median of all sites". The coverage section names the baseline population.

**Output per selection**

- One report for the selection. `--per-site` also writes one single-site report per selected site, with the same baseline scope, so the per-site files agree with the combined one.

### 6.7 Optional AI-written summary

Template prose is accurate but plain. For readers who want a write-up closer to an engineer's, `nic-report.py` supports a model-written summary **without ever calling a model itself**:

1. `--ai-brief FILE` writes a brief: the A1–A8 JSON (facts, findings, ranked recommendations, caveats) plus instructions. The guard rails are fixed and cannot be overridden. `--audience engineer|management|field` (default `engineer`) only selects tone and depth: full technical detail; impact, risk and next steps for managers; or per-site, per-port work orders for field technicians. Write prose only from these facts, cite recommendation IDs, invent nothing.
2. The operator sends the brief to a model of their choice, e.g. `claude -p < brief.txt > narrative.md`. That step, and the decision to send site data to an external service, is the operator's.
3. `--narrative FILE` merges the returned text into the report as a section clearly labelled **"AI-written summary"**, after a check:
   - every number in the text must appear in the facts (with unit-aware rounding),
   - every cited recommendation ID must exist.

   Failures are listed under the summary, and with `--strict-narrative` the merge is refused.

Tables, findings, statistics and the ranked recommendations always come from the deterministic analysis; the model only adds prose around them.

### 6.8 Optional themes (company branding)

Organisations can brand the HTML and PDF output without forking the tool or putting brand assets in the repo.

- **Selection:** `--theme DIR`, or the `NIC_REPORT_THEME` environment variable. Without either, the built-in neutral theme is used.
- **Theme folder** (kept by the operator, outside the repo, e.g. with the site data):

```
mytheme/
├── theme.json       # required
├── logo-light.png   # logo for light backgrounds (page header, HTML title)
└── logo-dark.png    # logo for dark backgrounds (PDF cover)
```

```json
{
  "schema_version": 1,
  "name": "example",
  "org": "Example Corp",
  "colors": { "primary_dark": "#0B1F44", "primary": "#1F4E99", "accent": "#4A90D9",
              "link_dark": "#7FB3E8", "header_bg": "#DDE3EA", "header_fg": "#0B1F44" },
  "fonts":  { "heading": ["Brand Sans Light"], "body": ["Brand Sans"] },
  "logos":  { "cover": "logo-dark.png", "header": "logo-light.png" },
  "labels": { "header_title": "NIC Health", "classification": "Internal" }
}
```

- **What a theme can change:** brand colours (cover, headings, links, table headers, section rules), font families (with the built-in fallbacks always appended), logos and placement (PDF cover, running page header, HTML title), organisation name, header title and classification label. Markdown and JSON never read a theme.
- **No free-form CSS:** a theme can't change content, severity colours, classification or attribution. (A block-listed `extra.css` was tried and dropped: CSS alone can relabel a badge, replace page margin boxes or hide text, and no allow-list fixes that while `color` exists.) An `extra.css` file in the folder is ignored with a warning.
- **What a theme cannot change:**
  - the **severity colours** (CRIT, WARN, OK, N/A, UNKNOWN), which stay distinct and readable regardless of brand palette,
  - the report structure and content,
  - the attribution line (§6.9) and the classification label's visibility: severity badges, attribution and classification keep fixed colours (on the PDF cover, on fixed bands).
- **Checks when loading:**
  - required keys and `#RRGGBB` colours are validated;
  - text contrast is checked (primary on white, header text on header background, white on the cover colour), and a ratio below 4.5:1 is a warning (with `--strict-theme`, an error);
  - logo files must be PNG, JPEG or SVG and are embedded as `data:` URIs inside `<img>`, so the output stays one self-contained file and an SVG logo cannot run script;
  - `name` is restricted to `[A-Za-z0-9._-]`; control and bidi characters are removed from `org` and the labels; files are read with a size bound and must stay inside the theme folder (no symlink escape);
  - the PDF engine fetches `data:` URIs only, so a reference inside an SVG logo is never followed.
- **Fonts:** a theme names fonts and does not ship them. WeasyPrint uses what is installed on the host, so list a metric-compatible free fallback (e.g. Carlito for Calibri). Embedding a commercial font in a PDF is subject to its licence, which is the operator's responsibility. Never list the emoji font explicitly (see §6.4).
- **Prototype:** a theme built from a corporate slide template (theme colours from `ppt/theme/theme1.xml`, logos from `ppt/media/`) produced the expected cover, page header and table styling with this schema, without code changes beyond the loader.

### 6.9 Attribution

Like `nic-xray` diagrams (`Generated by nic-xray vX.Y.Z — © YEAR Ciro Iriarte` plus a timestamp), every report identifies the tool that generated it:

- **Text:** `Generated by nic-report vX.Y.Z — © YEAR Ciro Iriarte · YYYY-MM-DD HH:MM:SS ±hh:mm`. The version comes from `SCRIPT_VERSION` and the year and timestamp from generation time, with the same format as the diagrams.
- **Where:**
  - HTML: under the title block and in the closing footer,
  - PDF: at the bottom of the cover and in the closing footer,
  - Markdown: the last line,
  - JSON: a `generator` object (`tool`, `version`, `generated_at`),
  - HTML and PDF metadata: `<meta name="generator">`, which WeasyPrint writes to the PDF Creator field.
- **Data provenance next to it:** the `nic-health` versions and sweep timestamps the report was built from (already in A1), so a reader can tell the analysis tool from the collection tool.
- **Not themeable:** rewording is impossible; the line keeps a fixed colour (on the PDF cover, a fixed band) and only follows the theme's body font. The PDF Creator always carries the generator.

## 8. 🩺 Related per-host check (belongs in `nic-health.sh`)

**Rx power relative to the host's own peers:** WARN when a linked port's module Rx power is ≥ 5 dB below the median of the same host's other linked ports with the same module compliance (needs at least 3 peers). This catches an attenuated fibre or dirty connector **before** symbol errors appear, while the value is still inside the module's own alarm range. Both low-Rx cases found during the prototype comparison read "OK" in `mlx5.deep.module` and would have been flagged by this rule. It is a per-host rule, so it goes into `nic-health.md` §7 as a deep check, not into `nic-report`.

## 9. 🔒 Security

- **No interactive credentials.** `ssh -o BatchMode=yes` and `sudo -n` only; a host that would prompt is recorded as `ssh-fail` / `sudo-fail`.
- **No remote `eval`, no inventory data in remote commands.** ssh always runs a string through the remote login shell (which may be POSIX `sh`), so the remote text is constant apart from values validated locally (level from a fixed list, integer window and limits); inventory fields are validated (§5.1, first character alphanumeric) and only ever reach ssh as separate arguments after `--`; local variables are always quoted. Remote output is treated as untrusted: the verdict must be one of the four known values before it reaches the manifest.
- **Remote lifetime:** remote text runs with `LC_ALL=C`; where the host has `timeout(1)` the tool is limited to the local limit minus 5 s, so a dropped connection leaves no long-running root process; an interrupt forwards TERM through each worker to its `timeout(1)` and `ssh`.
- **Host keys:** the SSH policy is left unchanged by default; `--accept-new-hostkeys` is explicit.
- **`--ship`:** the script arrives on the SSH connection's stdin and is written to a `mktemp` file under `/tmp` (0600, created exclusively, owned by the SSH user), removed by a remote trap on EXIT, HUP, INT and TERM. It never writes outside `/tmp` and never touches the package manager. It needs sudo rights for `bash /tmp/nic-health.*`, which amounts to unrestricted root for that user: documented, and the package is preferred where that is not acceptable.
- **Reports hold sensitive inventory** (host names, switch ports, addresses). HTML and PDF embed no remote resources, and the classification label is printed on every PDF page. Sweep directories are created with mode 0750.
- **Themes are untrusted input:** `theme.json` is validated, logos are embedded as images only (the PDF engine fetches `data:` URIs only), and there is no free-form CSS (§6.8). Report files are written atomically with mode 0640.
- **`nic-report.py` never makes network calls**, including for the AI summary: it only writes a brief and reads a narrative file (§6.7). The brief contains the same sensitive inventory as the report, and sending it anywhere is the operator's explicit action.
